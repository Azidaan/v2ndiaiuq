# guiaidn — сайт ФГБНУ «ИПИИ»

Сайт и CMS работают локально в Docker. Данные хранятся в PostgreSQL в постоянном Docker-томе и не удаляются при остановке или пересборке приложения.

## Запуск

1. Создайте `.env` по примеру `.env.example` и задайте одинаковый пароль PostgreSQL в `POSTGRES_PASSWORD` и в строке `DATABASE_URL`.
2. Запустите приложение:

   ```bash
   docker compose up --build -d
   ```

3. Откройте сайт: <http://localhost:8080>
4. Откройте CMS: <http://localhost:8080/admin>

Остановка без удаления данных:

```bash
docker compose stop
```

Команды одинаковы в macOS, Linux, Windows PowerShell и Windows Terminal. На Windows рекомендуется Docker Desktop с включённым WSL 2. Проект можно распаковать в любую папку: абсолютные пути компьютера в конфигурации не используются.

## Перенос на другой компьютер

В репозиторий входят исходники и схема базы, но не локальные Docker-тома. Для нового чистого запуска достаточно перенести репозиторий, создать `.env` и выполнить `docker compose up --build -d`.

Чтобы перенести также существующие материалы, пользователей и загруженные файлы, необходимо отдельно сделать резервную копию PostgreSQL и тома загрузок. Простое копирование Git-репозитория переносит приложение, но не данные из Docker-томов.

## Проверка целостности PostgreSQL

После импорта, миграции или восстановления базы запустите:

```bash
docker compose exec app pnpm db:check
```

Успешная проверка возвращает `"status": "ok"`. Команда проверяет пользователей, наличие активного главного администратора, сессии, обязательные поля материалов, уникальность адресов, JSON-метаданные и блоки визуального редактора. При нарушении целостности команда завершается с ненулевым кодом.

## Управление пользователями

Первый главный администратор создаётся из `ADMIN_EMAIL` и `ADMIN_PASSWORD`. Остальные пользователи добавляются главным администратором в разделе CMS «Пользователи». Новый пользователь обязан заменить временный пароль при первом входе.

Роли:

- главный администратор — пользователи и весь контент;
- администратор — создание, изменение и удаление контента;
- редактор — создание и изменение без удаления;
- наблюдатель — только просмотр CMS.

## Размещение на сервере

Проект рассчитан на VPS или другой хостинг с Docker Compose и постоянными томами. Для production необходимо:

- указать уникальные `POSTGRES_PASSWORD`, `ADMIN_EMAIL` и `ADMIN_PASSWORD`;
- установить `COOKIE_SECURE=true`;
- подключить домен и HTTPS через обратный прокси;
- направить обратный прокси на `127.0.0.1:8080` и не публиковать порт PostgreSQL в интернет;
- настроить регулярные резервные копии PostgreSQL и загруженных файлов;
- после запуска выполнить `docker compose exec app pnpm db:check`.

Обычный статический хостинг без Node.js, PostgreSQL и постоянного диска для этого проекта не подходит.


## Новости старого сайта

В контейнере приложения автоматически запускается проверка `http://guiaidn.ru/` через 30 секунд после старта, затем каждые 30 минут. Для этого Docker и контейнер приложения должны работать. Проверяются актуальная лента и архив текущего года; архивы прошлых лет импортируются отдельно. В разделе админки «Новости» и в визуальном редакторе есть виджет с результатом, временем следующей проверки (МСК) и кнопкой «Перенести сейчас». Ручной запуск доступен редакторам и администраторам; наблюдатель видит только состояние.

Синхронизация добавляет только отсутствующие новости. Ручной текст, даты, обложки, фокус, слайдер и отметки проверки существующих записей сохраняются. Новые записи приходят опубликованными и непроверенными. Ошибки страниц и вложений отражаются в виджете. Параллельные запуски защищены блокировкой PostgreSQL, результат последнего запуска хранится в базе. Для выключения расписания задайте `LEGACY_NEWS_SYNC_ENABLED=false` в `.env` и пересоздайте контейнер; кнопка ручного запуска продолжит работать.

Разовый запуск скриптом:

```bash
docker compose exec app node server/syncLegacyNews.mjs
```

Без сервера можно запустить самостоятельный процесс `node --env-file-if-exists=.env server/syncLegacyNews.mjs --watch`. Не требуется запускать его одновременно с приложением: приложение уже выполняет то же расписание.

Повторный исторический перенос:

```bash
node scripts/legacy-news/crawl.mjs 2018 2019 2020 2021 2022 2023
node scripts/legacy-news/audit.mjs --assets --fetch-sources
docker compose build app
docker compose up -d app
docker compose exec app node server/importLegacyNews.mjs
```

Исходные HTML и отчёты сохраняются в игнорируемой папке `backups/legacy-news/`; `--cache` у парсера повторно использует эти HTML. Проверенные редакторские уточнения заголовков, категорий и дат хранятся в `scripts/legacy-news/corrections.json`. JSON разных периодов не дублирует уже перенесённые страницы. `--update` у импортера заменяет содержимое и сохраняет только «Проверено» — для обычной синхронизации он не используется.

Галереи сохраняются в HTML как `div[data-gallery="1…4"]` с `figure[data-image-block="true"]`. Редактор позволяет добавить или перетащить блок картинки в текст, загрузить одну или несколько фотографий, разместить блоки рядом, поменять их порядок, вынести в отдельный ряд, добавить подпись и обрезать фото. Файлы можно перетащить с компьютера прямо в блок. На телефоне галерея перестраивается в одну колонку. Настройка «Скрыть обложку над текстом новости» убирает повтор на странице статьи, сохраняя картинку для карточек и слайдера. Отметка «Проверено» сохраняется сразу отдельным запросом и не сохраняет другие несохранённые изменения формы.
